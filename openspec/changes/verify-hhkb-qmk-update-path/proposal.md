# Proposal

## Why

HHKB Professional Hybrid（英語配列）を QMK 化して実用し、書き込みまで macOS で完結させたい。参考実装の l3tnun/hhkb_hybrid は純正の HID 更新経路で QMK を書き込むとしているが、書き込みツールは Linux 専用で、記述も手元では未検証である。書き込みは保証に影響し、失敗時の最終手段は分解を伴うため、QMK を書き込む前に自前の観測で前提を確かめる。

## What Changes

- 公式 keymap tool と実機の HID 通信を macOS 上で記録する Rust 製のロガーを追加する
- 純正の更新ファイル（HFB）を読み取り専用で解析する Rust 製 CLI を追加する
- 実機の接続状態を確認する Rust 製 CLI を追加する。送信できるのは、記録で確認し承認された固定のレポートだけとする
- 公式ツールの読み出し、キーマップ書き込み、純正ファームウェアの再書き込みを、この順に承認を得ながら記録する
- 観測結果と参考実装の記述を照合し、次の段階へ進むかを判断する記録を残す
- 範囲外:
  - 自作ツールからの書き込み、更新モードへの遷移
  - QMK のビルドと書き込み
  - バイナリの逆アセンブル

### 全体の段階

1. この change: 検証、読み取り専用ツール、公式ツールの通信の記録
2. 次の change: QMK のビルドと HFB 生成（Rust）
3. その次の change: macOS からの書き込みと純正への復帰（Rust）

この change の結論は書き込みの可否ではなく、次の段階へ進むかの判断とする。

## Capabilities

### New Capabilities

- `hid-traffic-capture`: 公式ツールと実機の HID 通信を記録し、許可のない送信を止める
- `hfb-inspection`: 更新ファイルの構造を読み取り専用で解析し、整合性を検査する
- `device-status`: 接続中の実機を安全に識別し、状態を読み取る
- `protocol-findings`: 観測結果を、根拠と検証状態つきで記録する

### Modified Capabilities

なし

## Impact

- Rust のワークスペースと、HID アクセス用の依存を新規に追加する
- 実機: 自作ツールからは承認された読み取りレポートのみ送信する。公式ツールの書き込みと更新は、段階ごとの承認後にユーザーが操作する
- 公式ツール: 実行中の通信を記録する。バイナリは変更しない。EULA との関係はユーザーが判断する
- リポジトリ: 純正 HFB、生の通信ログ、`.hks`、シリアル番号はコミットしない
