# firmware-update Specification

## Purpose

許可した純正の更新ファイルだけを macOS から実機に書き込み、失敗してもキーボードを復旧できる手順へ確実に案内できるようにする。

## Requirements

### Requirement: 許可した HFB だけを書き込む
CLI は、SHA-256 が許可リストと一致し、CRC と MD5 の検査に通った HFB だけを書き込まなければならない（SHALL）。検査を省略する手段を持ってはならない（MUST NOT）。

#### Scenario: 許可リストにない HFB
- **WHEN** SHA-256 が許可リストと異なる HFB を指定する
- **THEN** 理由を表示し、デバイスを開かずに 0 以外で終了する

#### Scenario: 整合性の検査に失敗する
- **WHEN** HFB の CRC か MD5 が一致しない
- **THEN** 理由を表示し、デバイスを開かずに 0 以外で終了する

### Requirement: 計画の段階では送信しない
CLI は、実機に何も送信せずに、HFB の検査結果、パケット数、接続状況を表示する段階を持たなければならない（SHALL）。

#### Scenario: 計画を表示する
- **WHEN** 許可された HFB で計画を実行する
- **THEN** 検査結果とパケット数を表示し、レポートは送信されない

### Requirement: 実機に触れる段階を分ける
CLI は、更新モードへの移行と本体の書き込みを別のコマンドにしなければならない（SHALL）。更新モードへの移行だけでは本体を書き込んではならない（MUST NOT）。

#### Scenario: 更新モードへの移行
- **WHEN** 更新モードへの移行を実行して、再列挙されたインターフェースが見つかる
- **THEN** 見つかったことと次の手順を表示し、本体を送信せずに終了する

### Requirement: 実行前に確認する
CLI は、実機に送信する段階の実行前に、段階ごとの確認文の入力を求めなければならない（SHALL）。確認を省略するオプションを持ってはならない（MUST NOT）。

#### Scenario: 確認文が一致しない
- **WHEN** 確認文と異なる入力をする
- **THEN** レポートを送信せずに 0 以外で終了する

### Requirement: 移行前に対象を確認する
CLI は、更新モードへの移行の前に、対象が USB の 1 台であること、公式ツールが実行中でないこと、応答の版が書き込む HFB の版と一致することを確認しなければならない（SHALL）。

#### Scenario: 版が一致しない
- **WHEN** 実機の応答の版が HFB の版と異なる、または版を読み取れない
- **THEN** 更新モードへ移行せずに 0 以外で終了する

#### Scenario: 対象が 1 台ではない
- **WHEN** USB の対象が 0 台または 2 台以上である
- **THEN** レポートを送信せずに 0 以外で終了する

### Requirement: 応答を確認して進める
CLI は、各レポートの応答を確認してから次のレポートを送らなければならない（SHALL）。応答が想定と異なるときは、後続を送ってはならない（MUST NOT）。

#### Scenario: パケット番号が一致しない
- **WHEN** 本体の送信の応答に含まれるパケット番号が送信したものと異なる
- **THEN** 後続を送らずに中止し、次の手順を表示する

#### Scenario: 応答がない
- **WHEN** タイムアウトまでに応答がない
- **THEN** 同じレポートを再送せずに中止し、次の手順を表示する

### Requirement: 失敗時に次の手順を案内する
CLI は、中止したときに、到達した段階と、やり直しと Linux からの復旧の手順を表示しなければならない（SHALL）。実機の状態を断定してはならない（MUST NOT）。

#### Scenario: 移行後に中止する
- **WHEN** 更新モードへの移行を送信した後に中止する
- **THEN** キー入力の可否で状態を確認するよう案内し、やり直しの手順と Linux からの復旧の手順を表示する

### Requirement: 再列挙後は更新用のインターフェースだけを使う
CLI は、更新モードへの移行の後、USB の 1 台の Usage Page `0xFF00` のインターフェースだけを選び直さなければならない（SHALL）。見つからないときに他のインターフェースへ送信してはならない（MUST NOT）。

#### Scenario: インターフェースが見つからない
- **WHEN** 待ち時間の間に更新用のインターフェースが見つからない
- **THEN** USB の抜き差しを案内し、見つからないまま時間が切れたら送信せずに 0 以外で終了する

### Requirement: 通信の記録
CLI は、実機に送信する段階の送受信を、所有者だけが読み書きできるログとして `local/` に残さなければならない（SHALL）。応答に含まれる個体情報を画面に表示してはならない（MUST NOT）。

#### Scenario: ログの権限
- **WHEN** 実機に送信する段階を実行する
- **THEN** ログが権限 0600 で作成され、本体のデータはパケット番号だけが記録される
