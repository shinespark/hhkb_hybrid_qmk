# firmware-update Specification

## Purpose

許可した HFB（公式ファームウェアと、手元で生成した QMK の `default`、`via`）だけを macOS から実機に書き込み、失敗してもキーボードを復旧できる手順へ確実に案内できるようにする。

## Requirements

### Requirement: 許可した HFB だけを書き込む
CLI は、SHA-256 が許可リストと一致し、CRC と MD5 の検査に通った HFB だけを書き込まなければならない（SHALL）。検査を省略する手段を持ってはならない（MUST NOT）。

#### Scenario: 許可リストにない HFB
- **WHEN** SHA-256 が許可リストと異なる HFB を指定する
- **THEN** 理由を表示し、デバイスを開かずに 0 以外で終了する

#### Scenario: 整合性の検査に失敗する
- **WHEN** HFB の CRC か MD5 が一致しない
- **THEN** 理由を表示し、デバイスを開かずに 0 以外で終了する

### Requirement: 計画の段階では送信しない
CLI は、実機に何も送信せずに、HFB の検査結果、パケット数、接続状況を表示する段階を持たなければならない（SHALL）。

#### Scenario: 計画を表示する
- **WHEN** 許可された HFB で計画を実行する
- **THEN** 検査結果とパケット数を表示し、レポートは送信されない

### Requirement: 実機に触れる段階を分ける
CLI は、更新モードへの移行と本体の書き込みを別のコマンドにしなければならない（SHALL）。更新モードへの移行だけでは本体を書き込んではならない（MUST NOT）。

#### Scenario: 更新モードへの移行
- **WHEN** 更新モードへの移行を実行して、再列挙されたインターフェースが見つかる
- **THEN** 見つかったことと次の手順を表示し、本体を送信せずに終了する

### Requirement: 実行前に確認する
CLI は、実機に送信する段階の実行前に、段階ごとの確認文の入力を求めなければならない（SHALL）。確認を省略するオプションを持ってはならない（MUST NOT）。

#### Scenario: 確認文が一致しない
- **WHEN** 確認文と異なる入力をする
- **THEN** レポートを送信せずに 0 以外で終了する

### Requirement: 移行前に対象を確認する
CLI は、更新モードへの移行の前に、対象が USB の 1 台であること、公式ツールが実行中でないことを確認しなければならない（SHALL）。公式ファームウェアの動作中は、応答の版が書き込む HFB の版と一致することも確認しなければならない（SHALL）。

#### Scenario: 版が一致しない
- **WHEN** 公式ファームウェアの動作中に、実機の応答の版が HFB の版と異なる、または版を読み取れない
- **THEN** 更新モードへ移行せずに 0 以外で終了する

#### Scenario: 対象が 1 台ではない
- **WHEN** USB の対象が 0 台または 2 台以上である
- **THEN** レポートを送信せずに 0 以外で終了する

#### Scenario: QMK の動作中
- **WHEN** QMK の動作中に更新モードへの移行を実行する
- **THEN** 版を確認するレポートを送らずに、移行の手順へ進む

### Requirement: 応答を確認して進める
CLI は、各レポートの応答を確認してから次のレポートを送らなければならない（SHALL）。応答が想定と異なるときは、後続を送ってはならない（MUST NOT）。

#### Scenario: パケット番号が一致しない
- **WHEN** 本体の送信の応答に含まれるパケット番号が送信したものと異なる
- **THEN** 後続を送らずに中止し、次の手順を表示する

#### Scenario: 応答がない
- **WHEN** タイムアウトまでに応答がない
- **THEN** 同じレポートを再送せずに中止し、次の手順を表示する

### Requirement: 失敗時に次の手順を案内する
CLI は、中止したときに、到達した段階と、やり直しの手順を表示しなければならない（SHALL）。実機の状態を断定してはならない（MUST NOT）。

#### Scenario: 移行後に中止する
- **WHEN** 更新モードへの移行を送信した後に中止する
- **THEN** キー入力の可否で状態を確認するよう案内し、やり直しの手順を表示する

### Requirement: 再列挙後は更新用のインターフェースだけを使う
CLI は、更新モードへの移行の後、USB の 1 台の Usage Page `0xFF00` のインターフェースだけを選び直さなければならない（SHALL）。見つからないときに他のインターフェースへ送信してはならない（MUST NOT）。

#### Scenario: インターフェースが見つからない
- **WHEN** 待ち時間の間に更新用のインターフェースが見つからない
- **THEN** USB の抜き差しを案内し、見つからないまま時間が切れたら送信せずに 0 以外で終了する

### Requirement: 通信の記録
CLI は、実機に送信する段階の送受信を、所有者だけが読み書きできるログとして `local/` に残さなければならない（SHALL）。応答に含まれる個体情報を画面に表示してはならない（MUST NOT）。

#### Scenario: ログの権限
- **WHEN** 実機に送信する段階を実行する
- **THEN** ログが権限 0600 で作成され、本体のデータはパケット番号だけが記録される

### Requirement: QMK の動作中は QMK のインターフェースで移行する
CLI は、QMK の動作中の移行で、Usage Page `0xFF60` のインターフェースだけに、32 バイトのレポートを送らなければならない（SHALL）。

#### Scenario: QMK の動作中の移行
- **WHEN** QMK の動作中に更新モードへの移行を実行する
- **THEN** `0xFF60` のインターフェースだけを開き、送信するレポートは 32 バイトである

### Requirement: HFB の種類で移行のコマンドを選ぶ
CLI は、QMK の動作中に QMK の HFB を書き込むときは `e0` を、公式ファームウェアの HFB を書き込むときは `f0` を送らなければならない（SHALL）。公式ファームウェアの動作中は `e0` を送らなければならない（SHALL）。

#### Scenario: QMK から QMK へ
- **WHEN** QMK の動作中に QMK の HFB で移行する
- **THEN** `e0` を送り、`f0` を送らない

#### Scenario: QMK から公式ファームウェアへ
- **WHEN** QMK の動作中に公式ファームウェアの HFB で移行する
- **THEN** 最初に `f0` を送る

### Requirement: 公式ファームウェアへ戻すときに VIA の設定を残さない
CLI は、`f0` が拒否されたとき、VIA の問い合わせに応答がない場合だけ `e0` へ進まなければならない（SHALL）。VIA が応答する場合は、更新モードへ移行してはならない（MUST NOT）。

#### Scenario: VIA に対応しない QMK
- **WHEN** `f0` が拒否され、VIA の問い合わせに応答がない
- **THEN** `e0` を送って移行する

#### Scenario: `f0` を持たない VIA 対応の QMK
- **WHEN** `f0` が拒否され、VIA の問い合わせに応答がある
- **THEN** 移行せずに理由と次の手順を表示して、0 以外で終了する

### Requirement: QMK の動作中は本体を書き込まない
CLI は、QMK の動作中に見えるとき、本体の書き込みを始めてはならない（MUST NOT）。

#### Scenario: QMK の動作中に書き込みを実行する
- **WHEN** USB の製品名やインターフェースが QMK の動作中を示す状態で本体の書き込みを実行する
- **THEN** レポートを送信せず、先に移行するよう案内して 0 以外で終了する

### Requirement: 書き込み先の種類を実行前に示す
CLI は、計画と確認文の表示で、HFB の種類（公式ファームウェア、QMK の `default`、QMK の `via`）を示さなければならない（SHALL）。

#### Scenario: 計画の表示
- **WHEN** 許可された HFB で計画を実行する
- **THEN** HFB の種類が表示される

### Requirement: QMK が応答しないときの案内
CLI は、QMK の動作中の移行で中止したとき、Esc を押しながら USB を接続して更新モードへ入る手順を、未検証であることとあわせて表示しなければならない（SHALL）。

#### Scenario: QMK の移行の応答がない
- **WHEN** QMK の動作中に移行のレポートの応答がない
- **THEN** 実機の状態を断定せず、手順と、未検証であることを表示する
